## 2026-08-13 — 任意系統 → 可操作網頁（View＋Play）

- 狀態：building  
- 來源：對話（「能不能把任何系統變成網頁版？不只看，還能直接用」；後續定調行為保真＋聊天簽核）  
- 為什麼（Why）：地圖／說明只能看；真正懂系統要能「填、走流程、換角色」；最好還能當輕量替代介面。  
- 做什麼（What）：分三層，不要承諾「任意系統一鍵變正式系統」：  
  1. **View**：說明／地圖網頁（只讀）  
  2. **Play**：沙盒可操作（填表、換角色、模擬簽核／條件；資料不進公司正式庫）← **已開工 `play/`**  
  3. **Run**：真上線可用（登入、存檔、通知、接 SharePoint／API）— 只對「表單＋流程型」系統務實  
- 怎麼做（How）：  
  1. 輸入先走 Artifact Lens → `map` 產出 system-map JSON（12345）。  
  2. Play：[`play/index.html`](../../play/index.html) — 抽出系統、欄位契約固定座標、聊天式送出／核准／請填／駁回。  
  3. Run：接主線 Approval（紙本風＋schema＋SharePoint／個人空間）。  
- 優點（Pros）：View／Play 啟動低；合行為保真（非像素複製）。  
- 缺點／風險（Cons）：Play 僅 localStorage；尚未多裝置／真身分。  
- 不做的替代方案：對話裡口頭模擬。  
- 完成後可查核的一句（若將來有產品）：打開 `play/` 能抽出系統並走完送出→核准→確認（或駁回結束）。  
- 待拍板：Play 是否再接 JSON 匯入 system-map；何時開 Run。  
- 難點診斷／保真範圍：見前則對話紀錄（行為契約；一流程一契約）。

## 2026-08-13 — 任意檔案鏡片（Artifact Lens）

- 狀態：building  
- 來源：對話（「不要丟程式／PDF 才看得懂；SQL／C#／Power Automate／學生版／地圖」）  
- 為什麼（Why）：下載來的東西語言各異，想直接「變成我看得懂的版本」或一張地圖，而不是自己硬啃原文。  
- 做什麼（What）：輸入任意產物（程式、流程匯出、PDF／文件、試算表），自動辨識類型，再用選定「鏡片」輸出：母語說明、學生版、或 system-map 地圖。  
- 怎麼做（How）：  
  1. 先做薄 Skill（本庫已開工：`約定/系統/artifact-lens/`），Cursor 裡丟檔＋一句話即可。  
  2. 鏡片：`native`（同領域白話）、`student`（學生可讀）、`map`（接 system-map 12345）。  
  3. 不做大產品站；與 SEED／AI Doc 有關時再接知識書路線。  
- 優點（Pros）：啟動成本低；已有 system-map 可接；合「先地圖再細節」口味。  
- 缺點／風險（Cons）：大檔／模糊 PDF 可能漏；Power Automate JSON 雜訊多；學生版易過度簡化。  
- 不做的替代方案：每次手動叫 `/system-map` 或口頭說「講成學生版」。  
- 完成後可查核的一句（若將來有產品）：丟進一檔，一分鐘內拿到可讀說明或一張 12345 地圖。  
- 待拍板：要不要升級成獨立產品／SEED 工具層；預設鏡片要不要固定成 `map`。
