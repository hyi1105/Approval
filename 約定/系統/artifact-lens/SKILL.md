# Artifact Lens（任意檔案鏡片）

目標：人不用先學會該語言，也能把「下載來的東西」變成可理解版本。  
本 Skill 是**薄路由**：辨識類型 → 選鏡片 → 輸出；地圖鏡片委託 [`../system-map/SKILL.md`](../system-map/SKILL.md)。

## 何時啟動

- 貼了／附了程式、流程匯出、PDF、截圖、試算表，要「看懂」
- 說：講成學生版、畫地圖、翻成白話 SQL／C#／Power Automate
- 不想自己判斷要用哪套方法論時

## 強制流程（Agent 必做）

1. **辨識類型**（可並行猜，標信心；不確定就標 `unknown` 並用最接近鏡片）
2. **選鏡片**（使用者有指定就聽；沒說 → 預設 `map` 若像系統／表／流程；其餘預設 `native`）
3. **輸出**（見下方格式；一次主輸出，不要三種全洗版）
4. **最多問 3 題**補關鍵缺口；其餘標待補

語言：台灣繁體中文。教學時標關卡與 %（見 [`../../核心.md`](../../核心.md)）。

## 類型 → 怎麼讀

| 偵測線索 | 類型 id | 讀法重點 |
|----------|---------|----------|
| `CREATE TABLE`／`SELECT`／`.sql` | `sql` | 表、鍵、篩選、誰讀誰寫 |
| `namespace`／`class`／`.cs`／ASP.NET | `csharp` | 進入點、依賴、資料進出、副作用 |
| Power Automate JSON／`trigger`／`actions`／`.zip` 流程 | `power_automate` | 觸發 → 動作鏈 → 條件／迴圈 → 連到哪系統 |
| 作業／練習註解、簡短 demo、課堂風格 | `student_code` | 題目意圖、對／錯思路、可改哪 |
| 表頭像欄位＋來源／角色／步驟 | `system_sheet` | **直接走 system-map** |
| PDF／長文／規格 | `doc` | 目的、角色、流程、資料、例外 |
| 其他 | `unknown` | 先一句「這像什麼」，再選最接近鏡片 |

## 鏡片（一次只用一個主鏡片）

| 鏡片 | 何時 | 產出 |
|------|------|------|
| `native` | 「變成 SQL／C#／PA 白話」 | 用該領域詞彙講清楚：這份在幹嘛、結構、風險點 |
| `student` | 「學生版／好讀」 | 更短、比喻多、少行話；可附 1～3 個檢查題 |
| `map` | 「地圖／系統／誰填誰用」 | 讀完 system-map Skill，產出 12345＋Mermaid |
| `play` | 「網頁版／可操作／模擬用」 | **行為保真沙盒**（非像素複製）：可編＝可編、不可編＝鎖、必填＝必填、資訊內容同、動作同；排列／視覺可不同。正式產物待重建。規則見 system-map `references/output-views.md` §G。真上線（Run）另走 Approval |

可加次要標籤（不另開長文）：`diff-risk`（改了會炸哪）、`glossary`（專有詞 5 個內）。

**誠實邊界：** `play` ≠ 取代任意正式系統。View／Play 對「表＋流程＋角色」最划算；厚客戶端／複雜 C#／整包 ERP 只能局部模擬或接 Run 專案。

## 輸出順序（同一畫面）

```
1 一句結論：這份產物在幹嘛
2 類型＋鏡片（一行）
3 主體（native／student 條列；map 則整圖 12345）
4 若有下一步：一句「你可再叫 student／map／native」
```

記憶錨（與 system-map 共用）：**3＝資料家**。程式檔也要標「資料從哪進、寫去哪」。

## 範例（給 Agent 對齊語氣）

使用者丟一段 SQL 並說「看懂」：

1. 結論：這支查詢從訂單撈未出貨單並依客戶彙總。  
2. 類型 `sql`｜鏡片 `native`（若說地圖則 `map`）。  
3. 主體：FROM／JOIN 誰、WHERE 篩什麼、輸出欄、可能的效能／權限雷。  
4. 可選：一句「要學生版或地圖跟我說」。

對齊範例見 [`references/example-sql.md`](./references/example-sql.md)。

不要：重貼整份原始碼當「說明」、三種鏡片一次灌滿、無限追問。
